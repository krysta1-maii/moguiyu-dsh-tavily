## 1 交付形态

0.7.0 把原来的单一 Host 入口拆成两个按运行位置区分的入口。

| 入口 | 运行位置 | 注册内容 |
| --- | --- | --- |
| `@moguiyu/dsh-tavily` | `cordis.patch.yml` 的 Host Loader 行 | `/api/tavily-usage`、`/api/tavily-manager`、Plugins 卡片载体、每次 Host 挂载一次的缺 key 警告 |
| `@moguiyu/dsh-tavily/tools` | preset 的 `config.plugins` | `tavily_search`、`tavily_extract`、`tavily_map`、`tavily_crawl`，`tool:tavily_search` 与 `tool:tavily_direct` 两段提示，该安装实例的 round-robin 游标 |

包根入口不再注册模型工具或提示段，`package.json` 增加 `./tools` 出口，版本升至 0.7.0。Host 行仍由包内 `cordis.patch.yml` 插入，bundle 不修改任何 preset。

实际挂载与计划 §4.4 有一处差异：目标 preset 从四个调整为三个。`standard-instant`、`ptc-instant`、`cordis-ptc` 各带一行 `tavily-tools`；`chat-assistant` 已废弃，不挂载，其描述中仍保留“Tavily 联网搜索”字样，属于该 preset 自身的文案遗留。`minimal` 与官方 `standard`、`ptc`、`cordis` 均无该行。

### 4.2 preset registry 报告

启动输出不打印 preset 的 broken 警告，因此“日志干净”不能证明 preset 健康。施工期用 `@deepseek-ai/dsh-app-boot` 的 `loadLayeredEnv` 与 dsh 的 `runProfile` 在进程内启动同一 profile，读取 `ctx.get("agentPresets").list()` 与 `inspectCompositions()`，随后 shutdown。结果如下：

| 检查项 | 结果 |
| --- | --- |
| 八个 preset 的 `broken` | 全部为 `null`（standard、standard-instant、ptc、ptc-instant、minimal、cordis、cordis-ptc、chat-assistant） |
| 挂载 `@moguiyu/dsh-tavily/tools` 的 preset | 恰为 `["ptc-instant","standard-instant","cordis-ptc"]` |
| Host 全局工具目录中的 `tavily_*` | 空数组，说明四个工具没有回到全局层，未挂载该行的 preset 不会继承 |
| 启动耗时 | 约 8.8 秒，进程 shutdown 后正常退出 |

### 4.3 broken 诊断的对照实验

为确认 registry 报告能真实反映 preset 故障，施工期临时向 `chat-assistant` 插入一行 `name: "@moguiyu/dsh-tavily/does-not-exist"` 后重跑同一脚本：

```
{ "id": "chat-assistant", "broken": "tavily-probe-broken (@moguiyu/dsh-tavily/does-not-exist): never started" }
```

其余 preset 仍为 `null`。删除该探针行后重跑，`chat-assistant` 恢复 `null`，挂载 tools 的三个 preset 不变。因此 4.2 的 `null` 是有效证据，而不是“日志本来就不报错”。

## 5 验收结论

用户确认：当前验收结果全部符合 0.7.0 的设计预期。该结论覆盖以下设计预期，前面的命令、registry 结果与文档检查提供对应证据。

| 设计预期 | 对应证据 |
| --- | --- |
| Host 入口与 preset 入口各司其职 | 入口测试、合成树、registry 报告与当前实例的路由检查 |
| 工具只出现在显式挂载 tools 入口的 preset 中 | registry 显示恰好三个 preset 挂载，Host 全局工具目录中没有 `tavily_*` |
| Plugins 卡片与两条管理路由保持可用且唯一 | 重复 exact 路由测试、临时实例与当前实例的 200 响应、Client 产物检查 |
| 凭据与可用性状态跨 preset 共享，round-robin 游标按安装实例独立 | 两个安装实例的游标测试、priority 顺序测试与源码边界 |
| 开关、卸载与回滚语义已写入文档 | 卡片文案、README 的开关与卸载章节、本文第 7 节 |

结论：0.7.0 的入口分离、工具可见性、管理面与状态语义符合设计预期。

## 7 回滚

0.7.0 的回滚必须同时恢复包与 profile 的 preset 声明：

1. 停止 Harness；
2. 从三个 preset 删除 `- id: tavily-tools` / `name: "@moguiyu/dsh-tavily/tools"`；
3. 用备份 `~/.dsh-local-plugins/dsh-tavily.0.6.0-backup-20261102T033512Z` 覆盖回 link 目标，或按 0.6.0 产物重装；
4. 或用 profile 备份 `cordis.patch.yml.bak-before-tavily-0.7.0-20261102T033533Z` 恢复预设声明；
5. 启动 Harness，确认所有 preset 恢复 Host 全局 Tavily 工具，卡片与两条路由正常。

`~/.dsh/tavily-manager.json` 的 schema 未变，不需要数据回滚。只回滚包而不删除 tools 行会让 preset 因缺少 `/tools` 出口而 broken；只删除 tools 行而保留 0.7.0 会让所有 preset 都没有 Tavily 工具。两种不完整状态都不作为结束状态。
