## 2 0.2.2-rc.5 契约核对结论

直接核对本机安装的 DSH `0.2.2-rc.5` 源码：

1. `ctx.connection.fetch.register(route)`（`@deepseek-ai/dsh-client-connection@0.2.2-rc.5`）：
   - `ConnectionFetchRoute` 包含 `path`、`methods`、`requestBody: 'buffered' | 'streaming'`、`fetch: (request: Request) => Promise<Response>`，返回异步 disposer `() => Promise<void>`。
   - `fetchRoutes` 按 `path` 唯一索引，重复注册抛 `connection: exact Fetch route "<path>" is already registered`。
   - `createSharedFetchHandler('/api')` 仅允许 `peer.principal.kind === 'owner'` 访问 exact route，非 owner 返回 `403`；未认证或未通过 Host/Origin 检查的请求在 `connection.admit(req)` 阶段返回 `401` / `403`，不进入业务处理器。
   - **关键契约偏差修订**：`http-bridge.ts` 在 `bodyMode === 'streaming'` 时对所有匹配方法构造 `new Request(url, { method, headers, body: Readable.toWeb(req), duplex: 'half' })`，而 Node 24 WHATWG Fetch 禁止 `GET`/`HEAD` 带 `body`（直接抛 `TypeError`）。因此把管理写接口拆分为独立流式路径 `POST /api/tavily-manager/update`（`requestBody: 'streaming'`），`GET /api/tavily-manager` 与 `GET /api/tavily-usage` 保持原路径并使用 `requestBody: 'buffered'`。
2. `HarnessError`（`@deepseek-ai/dsh-error@0.2.2-rc.5`）：
   - 构造签名 `new HarnessError(message, code, options?)`，与 `@deepseek-ai/dsh-llm` 导出同一类引用。
   - `@deepseek-ai/dsh-tools` 的 `ToolExecutionPipeline` 通过 `error instanceof HarnessError` 投影 `{ name, code }`，并对 `signal.aborted && isUnclassifiedCancellation(error, signal)` 归类为 `AbortError` / `ABORTED`。
3. `credentials/reference-updated`（`@deepseek-ai/dsh-credentials@0.2.2-rc.5`）：
   - 事件签名 `(ref: CredentialRef) => void`。

| 浏览器 UI 交互 | 无自动化浏览器控制 | 由用户在安装后于 Web UI 核对 |
