## 2 0.2.2-rc.5 契约核对与计划偏差

施工前核对本机安装的 DSH `0.2.2-rc.5` 源码，确认一处必须修订的契约细节：

1. `@deepseek-ai/dsh-client-connection@0.2.2-rc.5`（`src/rpc-host.ts`、`src/http-bridge.ts`）：
   - `ConnectionFetchRoute` 按 `path` 唯一注册，`requestBody: 'buffered' | 'streaming'` 绑定在整条路由而非单个 HTTP 方法上。
   - `http-bridge.ts` 在 `bodyMode === 'streaming'` 时直接构造 `new Request(url, { method, headers, body: Readable.toWeb(req), duplex: 'half' })`；Node 24 WHATWG Fetch 对 `GET`/`HEAD` 传入 `body` 会抛出 `TypeError: Request with GET/HEAD method cannot have body.`。
   - **已采纳的偏差修订**：将管理写接口拆分为 `POST /api/tavily-manager/update`（`requestBody: 'streaming'`），在 `http-bridge.ts` 默认 300 MiB 缓冲之前强制实施 64 KiB 流式上限；`GET /api/tavily-manager` 与 `GET /api/tavily-usage` 保持原路径并使用 `requestBody: 'buffered'`。`src/client.js` / `lib/client.js` 已同步更新所有 POST 调用路径。
   - 对于未声明在 `route.methods` 中的方法，Connection 共享通道不进入 `route.fetch`（按共享通道返回 `404`）；处理器内部仍保留防御性 `405` + `Allow` 头。
2. `@deepseek-ai/dsh-error@0.2.2-rc.5`：
   - `HarnessError(message, code, options?)` 与 `@deepseek-ai/dsh-llm` 导出同一类引用，`@deepseek-ai/dsh-tools` 管线通过 `error instanceof HarnessError` 投影 `{ name, code }`。
3. `@deepseek-ai/dsh-credentials@0.2.2-rc.5`：
   - 事件 `credentials/reference-updated` 签名为 `(ref: CredentialRef) => void`。
