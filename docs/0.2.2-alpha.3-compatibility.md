# @moguiyu/dsh-tavily 0.7.1 与 DSH 0.2.2-alpha.3 的兼容性核对

- 目标版本：DSH `0.2.2-alpha.3`，tag `dsh-v0.2.2-alpha.3`，commit `05b1cae8db6e674c5685101494d4eec24652424a`
- 本机安装：DSH `0.2.1-rc.5`，Node `v24.22.1`；本次不升级本机安装，也不声称完成真实 0.2.2-alpha.3 实例验收
- 核对日期：2026-11-03（Asia/Hong_Kong）
- 结论：接口契约兼容，未发现阻断性不兼容；0.7.1 将 0.2.2 作为整条版本线声明

## 1 版本声明

0.7.1 在 `package.json` 的 `dsh.compatibility.dshReleases` 中增加 `0.2.1-rc.5` 与 `0.2.2`，并在两个 `@deepseek-ai/dsh*` peer 范围的末尾追加 `^0.2.2-0`。该范围覆盖 0.2.2 的 alpha、rc 与正式版；按 0.x caret 规则，它也接受 0.3.0 之前的后续 0.2.x。旧的 `^0.2.0-0` 与 0.1.x 范围保留。

没有新增 `engines.dsh`。DSH 的兼容门禁在存在 `engines.dsh` 时只按它判断并忽略 peer；新增一个窄范围会把仍在支持的 0.1.x 与 0.2.0、0.2.1 行排除在外。当前 peer 回退在门禁的 `includePrerelease` 匹配下已经覆盖 0.2.2-alpha.3，追加 `^0.2.2-0` 是为了让普通 semver 读者也能明确看到这条版本线。

## 2 核对项

| 检查面 | 结果 |
| --- | --- |
| 兼容门禁 | `evaluatePluginCompatibility` 对 `0.2.2-alpha.3` 返回 `compatible`；`0.3.0` 被拒绝 |
| Host 入口 | `name` / `inject` / `apply` 与 `webServer`、`credentials` 服务一致 |
| 管理路由 | `webServer.register` 的 exact 路由签名一致；重复路径仍抛错；与 `/api` 前缀不冲突 |
| 凭据 | `resolve` / `describe` / `set` / `unset` 与 `CredentialInfo.writable` 一致 |
| 工具定义 | 四个 `defineTool` 定义通过 0.2.2-alpha.3 的 schema 编译；输出可生成 TypeScript 类型 |
| 工具执行 | `execute(args, exec)` 与 `exec.signal` 一致；mock 401 换到下一个 key 的流程正常 |
| 提示段 | `systemPrompt.section({ name, order, text })` 一致 |
| 主目录 | `resolveDshHome` 仍从 `@deepseek-ai/dsh-home-paths` 导出 |
| Client 声明 | `dsh.client` 的 `platform` / `inject` 通过 `parseDshClient` |
| Client 产物 | 字符串 `exports["./client"]`、`__ModuleLoader__.load` factory、`react` 基线模块均可用 |
| 卡片槽位 | `plugins.bundle.config` 仍为 keyed、root 作用域；`page` / `summary` 视图一致 |
| 样式变量 | 卡片使用的 `--dsw-alias-*` 仍存在；warning token 有本地回退色 |

## 3 实际执行的检查

`npm run check` 通过。`npm test` 在现有依赖下 65 项全部通过。把 `@deepseek-ai/dsh-tools` 与 `@deepseek-ai/dsh-home-paths` 通过 Node loader hook 指向 0.2.2-alpha.3 的本地构建产物后，同一套测试仍为 65 项全部通过；这两个包在该 tag 与构建树之间没有源码差异。

冒烟检查另行确认了以下行为：注册四个工具与两段提示；四个输出 schema 通过 `assertSupportedJsonSchema`；mock 第一个 key 返回 401 后换到第二个 key；Host 入口登记两条 exact 路由；Client bundle 在 VM 中注册出 `id`、`factory`、`apply`，并把卡片写入 `plugins.bundle.config`；兼容门禁对 `0.2.2-alpha.3` 返回 `compatible`。

## 4 0.7.1 内的相关清理

删除 `src/invariant.js` 与 `package.json` 的 `./invariant` 出口。`invariants` 服务从 DSH 0.2.0-rc.2 起已移除，该文件既没有被 `cordis.patch.yml` 挂载，也不会被自动加载；0.7.0 的历史施工计划仍写着“保持原样”，那是当时的记录。工具错误与启动警告中的 “Tavily Search settings card” 改为 “Tavily card on the Plugins page”。README 增加 0.2.2 的 Node 24.9 下限与 preset 执行器迁移说明。

## 5 未覆盖

没有启动真实的 DSH 0.2.2-alpha.3 实例，因此未验证真实组合下的行激活、浏览器卡片渲染与交互、PTC 模式下的 SDK 调用、真实 Tavily 请求、HMR 与远程访问。第 3 节的 fake `ctx` 不能代替真实 Cordis 组合。

## 6 后续可选项

本地化（包根 `locale/*.json` 与卡片正文接入 `ctx.locale`）、`/api/tavily-manager?reveal=` 的回环地址校验、`@deepseek-ai/cordis` peer 范围与开发依赖的版本对齐，均不影响本次 0.2.2 兼容结论，留待后续版本处理。
